# Characters — `havoc` / `aegis`

Generated by `tools/assets/build_characters.py` (rerunnable, idempotent):

```sh
python3 tools/assets/build_characters.py            # both teams
python3 tools/assets/build_characters.py aegis      # one team
TS_ZONE_DEBUG=1 python3 tools/assets/build_characters.py havoc   # flat debug hues
```

Source: Quaternius **Ultimate Toon Shooter** (CC0) —
`/opt/assets_cc0/toonshooter/Characters/Blends/Character_Soldier.blend`
(both bodies) plus `Character_Enemy.blend` (Havoc's hood).

| File | Contents |
|---|---|

| `aegis.glb` | defenders — 2976 tris, 1 material, 1 texture |

Both are 1.80 m tall in the rest pose, Y-up, facing −Z (Godot forward).

## Team read

Both teams share the **same body mesh** (the Soldier body — it is the one with a
plate carrier, mag pouches and a belt as real geometry) so they animate and
budget identically. They differ in headgear, shoulders and palette:

|  | Havoc (attack) | Aegis (defend) |
|---|---|---|
| head | Enemy character's **hood** + face wrap, dark eye slot | **helmet** + navy band, bare face, balaclava |
| shoulders | none | **pauldrons** |
| palette | desert: khaki fatigues, brown leather rigging, `#FF7A1A` armband | cool: slate blue-grey uniform, black nylon rigging, `#2E5FA8` band |
| arms | rolled sleeves, bare forearms + hands | long sleeves, black gloves |

Hood-vs-helmet plus pauldron-vs-none plus warm-vs-cool is readable as a
silhouette at distance, which is what team ID needs.

## Scene structure (as Godot imports it)

```
havoc            (Node3D)              <- scene root
├─ CharacterArmature      (Node3D)
│  └─ Skeleton3D          (Skeleton3D, 43 bones)
│     ├─ Index1_R         (BoneAttachment3D, bone = "Index1.R")
│     │  └─ WeaponMount   (Node3D)     <- parent the third-person weapon here
│     ├─ Body             (MeshInstance3D, 1 surface)
│     └─ Head             (MeshInstance3D, 1 surface)
└─ AnimationPlayer        (17 animations)
```

`Body` and `Head` are **separate meshes on purpose** and must stay that way:

```gdscript
# full-body first person: hide your own head so it does not fill the camera
character.find_child("Head", true, false).visible = false
```

`Head` holds the whole head — skull, face, balaclava and helmet/hood — so
hiding it leaves nothing in front of the camera. Both meshes share one
`StandardMaterial3D` instance, so the pair is 2 draw calls, 1 texture.

## Bones the gameplay code needs

The rig is the stock 43-bone ToonShooter humanoid, shared by every character in
the pack, so animations are interchangeable.

| Purpose | Bone | Notes |
|---|---|---|
| **weapon attachment** | `Index1.R` | use the `WeaponMount` child node, not the bone directly |
| left-hand support grip | `Index1.L` | mirror of the above, no marker emitted |
| **head** (FP camera, head-look) | `Head` | bone origin at 1.22 m, eye line ≈ 1.52 m |
| **spine / aim pitch offset** | `Torso` | upper spine, origin 0.86 m — rotate this for the aim offset |
| secondary spine | `Abdomen`, `Hips` | 0.62 m / 0.38 m, for lean and crouch offsets |
| root motion / whole-body | `Root` | at the origin, on the floor |
| feet (IK) | `Foot.L`, `Foot.R`, `PoleTarget.L`, `PoleTarget.R` | stock IK targets, keyframed by the source animations |

Careful: **there is also a bone named `Body`** (the pelvis/base bone, between
`Root` and `Hips`). It is unrelated to the `Body` mesh node. Node lookups and
bone lookups use different namespaces, so this is safe, but do not confuse them
when reading animation tracks.

Full list: `Root`, `Body`, `Hips`, `Abdomen`, `Torso`, `Neck`, `Head`,
`Shoulder.L/R`, `UpperArm.L/R`, `LowerArm.L/R`, `Thumb1-2.L/R`,
`Index1-3.L/R`, `Middle1-3.L/R`, `Pinky1-3.L/R`, `UpperLeg.L/R`,
`LowerLeg.L/R`, `Foot.L/R`, `PoleTarget.L/R`.

### WeaponMount convention

`WeaponMount` sits in the right palm, oriented so a weapon built to the
pipeline convention (**barrel +Z, grip −Y**, see `docs/ASSET_PIPELINE.md`)
lands correctly with an *identity* local transform:

```gdscript
var wpn := (load("res://assets/weapons/<id>/tp.glb") as PackedScene).instantiate()
character.find_child("WeaponMount", true, false).add_child(wpn)
# wpn.transform stays identity; nudge with the weapon's own GripR marker if needed
```

Verified by attaching a proxy rifle and rendering `Idle_Shoot` — the barrel
points down the aim line and the grip sits in the hand.

## Colour variants (so bots do not all look identical)

Each team ships two atlases over **identical geometry and UVs**: the mesh's UVs
address slots in an 8x8 palette grid, and the variant only repaints those slots.
Variant B shifts the fatigue / hood / trouser / sleeve and skin tones.

Variant A is already the material baked into the `.glb`, so it costs nothing.
For variant B, override the surface material with the same settings and a
different albedo texture. Build the materials **once** and share them across
every bot, or the draw-call saving is thrown away:

```gdscript
const ATLAS_B := {
    "havoc": "res://assets/characters/havoc_atlas_b.png",
    "aegis": "res://assets/characters/aegis_atlas_b.png",
}
static var _variant_b: Dictionary = {}

static func variant_b_material(team: String) -> StandardMaterial3D:
    if not _variant_b.has(team):
        var m := StandardMaterial3D.new()
        m.albedo_texture = load(ATLAS_B[team])
        m.roughness = 0.72
        m.metallic = 0.0
        m.texture_filter = BaseMaterial3D.TEXTURE_FILTER_LINEAR_WITH_MIPMAPS
        _variant_b[team] = m
    return _variant_b[team]

func apply_variant(character: Node3D, team: String, variant: int) -> void:
    var mat: Material = null if variant == 0 else variant_b_material(team)
    for name in ["Body", "Head"]:
        (character.find_child(name, true, false) as MeshInstance3D).material_override = mat
```

Verified by swapping the atlas file and re-rendering: the same UVs pick up the
recoloured slots with no seams.

## Notes for later phases

* The `<team>_atlas.png` files are both the standalone texture *and* the texture
  Godot extracts from the `.glb` (the embedded glTF image is named `atlas`, so
  the extraction path collides with the authored file instead of duplicating
  it). Godot only writes it when it is missing, so the committed PNG wins.
* `assets/characters/*_atlas*.png.import` currently sits at Godot's default
  `compress/mode=0` with `detect_3d/compress_to=1`; the engine flips it to VRAM
  (ETC2/ASTC, per `project.godot`) the first time the texture is seen on a 3D
  material in the editor. Worth confirming before shipping an Android build.
